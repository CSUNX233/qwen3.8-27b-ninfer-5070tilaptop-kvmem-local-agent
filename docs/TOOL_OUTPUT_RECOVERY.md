# 工具输出解析修复（2026-10-20，第一批）

本轮基于 v0.1.3 源码 `389791f834880e77f31fcb46ebe288918074882e`，只处理工具输出解析。
参考 NInfer 上游的 [Markdown 保护](https://github.com/iamwavecut/ninfer-all/commit/81e29890a74b81801bdb6daeaffee1c631807a6a)
和 [未闭合思考恢复](https://github.com/iamwavecut/ninfer-all/commit/99ff511900f73130906abe3fe1d7e1025d04b746)，
按本分享包的解析器、输出提交及日志接口适配，没有整体更新上游。

## 行为

- 围栏代码及行内代码中的工具 XML 保留为文本，整段输出与逐字节流式解析保持一致。
- 对上游进一步补齐多反引号分隔符、转义反引号和 tilde 围栏首行的保护。
- 模型自然触发 StopToken、思考尚未闭合、没有正文时，若末尾仅包含完整且已声明的工具调用，返回结构化调用。
- 思考原文仍在 reasoning 中；不会把思考复制成正文。未声明工具、残缺参数/封套、调用后的继续思考、代码示例不触发恢复。
- 客户端 stop string、取消、输出或上下文额度耗尽不触发恢复。强制调用、raw 输出及 grammar 约束路径保持原契约。
- 本分享包对正文中多余参数闭合标签的容错保留，但新增的思考恢复使用更严格的读取方式。
- 增加 `recovered_from_reasoning` 诊断及 Info 日志；本分支请求日志 schema 从 27 升到 28，配套语料读取器同步。

此修复只覆盖一种提前结束：模型已经输出调用，却把它留在未闭合思考里。它不保证普通长文总能达到要求长度，不改变 EOS 采样，也不添加自动续写。
MTP 分区一致性、anchor 归属及共享候选筛选尚未移植。

## 成本

未新增 CUDA 工作区、未改 KV 编码、权重、xhigh、采样、检索窗口或页预算。存在工具的开放思考阶段多保留一份普通 RAM 文本；思考关闭后清空，成本随该请求的思考字节数增长。
另有 CPU Markdown 跟踪及结束时解析开销。工具是否真正执行仍由客户端决定。

修复前，最初 Markdown 定向夹具出现 14 处失败，最终扩展夹具在原版解析器上出现 18 处失败；开放思考的单次及逐 token 提交夹具均返回 0 个工具调用。
修复后，两项独立定向测试、日志测试及 Python serving-corpus 2 项检查通过。
测试入口：

```text

ninfer_qwen3_5_tool_recovery_test
ninfer_request_log_test
```

全量已有解析器组修复前为 27/35，通过新增检查后为 30/38；前端组为 52/53 → 53/54。
第一批验收时，原有 8 个解析器失败及 1 个前端失败在前后对照中均存在，没有新增失败。
随后已逐项定位并修复，原因及 39/39、54/54 结果见[原有失败修复](TOOL_PARSER_EDGE_CASES.md)。本页下述哈希与真实模型数据保留为第一批的历史证据。
为避免旧测试中一项异常中止遮住后面的结果，本机逐函数在独立进程中执行前后对照。

构建使用 CUDA 13.0.48 / MSVC 14.44.35207 / sm120a，重建 v0.1.3 全部本地替换单元，并重编输出解析和全部 serving 结果消费者；其余原静态库复用。
这不是干净全量构建。本机没有重新配置旧 CMake 构建树，实际使用等价的独立增量编译/链接执行定向检查。

| 检查 | 结果 |
|---|---|
| 短工具调用、工具结果续接 | 均通过 |

候选长召回冷预填充约 674.44 秒、生成约 85.35 token/s，仅为这次运行的观察值。
旧引擎的 204854-token 召回也为 10/10，但旧夹具在召回后才添加工具目录，改变前缀并引发整段重读；该后续请求由维护操作主动停止。
候选已从第一轮固定目录。两轮输入与生成文本不同，不能把耗时直接当成修复带来的速度提升，旧引擎也没有完成对应的长工具续接对照。

6 次真实请求均未自然触发 `recovered_from_reasoning`。它们验证常规调用、缓存续接与示例保护；新增开放思考恢复分支的正确性来自前述确定性夹具，不宣称已测得真实任务成功率提升。
本轮是引擎 API 与合成工具结果检查，未执行完整 dsh / 浏览器任务链、满 256K 或多 seed 质量测试。
