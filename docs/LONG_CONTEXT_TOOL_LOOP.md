# 重复工具调用定位与底层采样边界候选（2026-10-20）

针对[扩展验证](EXPANDED_VALIDATION.md)中的约 98.6K 输入失败：模型思考中已取得 8 个校验码及两项计算结果，最终却调用 `read_record`，明确纠正后仍重复调用。本项与[群友 DSH 五分钟流空闲超时](DSH_STREAM_TIMEOUT.md)分别跟踪。

## 已确认的范围

- 删除背景档案、保留相同清单、问题和工具后，输入仅 818 tokens；原引擎顺序测试 10 个 seed 中 9 个成功，`20359325` 在相同请求顺序与缓存条件下可复现。重启复测不能直接等同于单请求冷启动；下方追加对照已确认候选的冷、热输出会不同。它不是只在长上下文发生的召回失败。
- 错误样本思考中的事实和计算正确，但最终正文为空。因此仍按失败计分，不能把思考内容拿来冒充最终回答。
- 请求为 `tool_choice=auto`，没有强制工具名称，也没有启用结构化输出语法。调用经正常标记解析产生；本轮没有触发未闭合思考恢复、猜测式补全、输出限长、CUDA 错误或页池耗尽。
- MTP3 保留、只对临时实例关闭 n-gram：10 个短测、原始 98K 请求及旧失败历史纠正均通过。临时关闭全部草拟：3 个短测、98K 及纠正也通过。不同草拟路径改变随机数用途和数值路径；这些结果不能单独证明 n-gram 算法有 bug，也不能当作总体质量统计。
- 链接当前实现的 `test_speculative_round.cpp` 完整独立校验通过，覆盖接受/拒绝、惩罚计数、mask、不同词表和批量、Graph 及非有限数拒绝。它排查的是这些内核契约，不能排除所有模型状态问题。

## 发现的思考后采样边界

临时诊断引擎仅增加输出日志，输出与原引擎相同。失败短测在思考规范闭合的同一轮还产出了一个 `<tool_call>` token；现有 `apply_post_thinking_sampling` 在该轮提交后、下一轮开始前才切换参数。因此该标记仍用思考阶段采样生成。

这是已确认的切换边界行为，成功样本也可跨越该边界。后续已实现验证前限制草拟长度的候选，下文列出结果；没有使用非终止部分提交或撤销已写状态。该边界问题不能单独解释所有误调用。

## 第一轮缓解候选

原模板说明了调用格式，并在“没有工具可用”时提示正常回答；补充三条工具选择说明：资料足够则直接回答、遵循当前轮是否使用工具的要求、完成的调用仅在需要更新信息或结果不全/失败时重试。工具名称和参数格式、原消息及思考序列化保持原逻辑。

这是提示词层面的行为缓解，不是 CUDA、KV 或事务修复。候选保留 NVFP4、xhigh、MTP3、n-gram15、生产采样、上下文上限及页预算。测试中模板增加 89 个 prompt tokens；会使已有前缀缓存失效并重建，不增加常驻 GPU 工作区。没有通过关键词强行关闭工具，也没有去重合法重复读取。

候选短测 10/10 通过，但原始 98K 请求仍在算对后调用工具，最终正文 0/10；旧失败历史纠正通过。由于长测失败，依赖它的工具续接没有执行。此模板候选未应用，后续底层测试均恢复原模板。

## 底层候选的实现与边界

仅在请求具有思考后采样覆盖、且尚未切换时，Scheduler 向 Program 传递思考关闭 token。MTP 验证前检查神经草拟及 n-gram copy proposal，遇到关闭 token 时把有效草拟长度限制在其之前；关闭标记只能作为这一轮最后的 target bonus/correction 被许可。这样不会在同轮许可标记后的正文。

模型词表中的 `</think>` 是单独 token，但 `special=false`；因此必须依据 tokenizer 的精确单 token 编码识别，不能硬编码 id 或要求 special 标记。关闭标记提交后，下一轮只许可一个 target token 来确认分隔符；引用中的 `</think>'` 等不切换。前端以已提交的呈现解码状态确认闭合，raw 模式保持原规范序列边界；采样切换与前缀缓存规范分段仍分别记录。

候选保持 NVFP4、xhigh、MTP3、n-gram15、原采样值、模板、262144 上限及原页预算。没有屏蔽工具、吞掉重复调用、缩短思考或复用思考里的 JSON 作为答案。没有新增 GPU buffer；闭合附近可能多执行 target 步，改变随机数用途、生成序列和接受率。不能保证总体提速或总体质量提升。

本次只实现并验证 MTP 路径，未将同样的 proposal 截断扩展到 DFlash。若 tokenizer 不能将关闭标记编码为一个精确 token，则没有此草拟屏障；不能将本模型的结果推广到所有 tokenizer。

## 实际验证与剩余问题

已链接候选对象执行：前端完整程序 55 组、解析器 39 组、18 个 Host 测试程序全部通过；新增断言覆盖 preview/commit、非 special 关闭 token、引用/分隔符、raw 规范分段、EOS 后未接受后缀、Scheduler 采样覆盖与预算耗尽、proposal 边界位置。另有独立 `test_speculative_round.cpp` 基线校验通过，不代表整模型状态均已排除。

完整 v2 候选短测 8/10，旧引擎为 9/10。原始 98,592-token 请求返回最终答案 10/10，旧失败历史纠正也为 10/10；随后三次显式工具调用和三次结果续接全部通过，包括再次合法读取同一 record。纠正轮与该续接属于不同历史分支，第一次工具调用缓存为 0、重读约 165 秒；后续五轮命中约 101K 历史。不能把分支重读记作流卡死，也不能声称这六轮全为热缓存。

临时探针确认草拟已在关闭 token 之前截断，关闭后分隔符独立执行，仍失败样本的 `<tool_call>` 在回答阶段 `temperature=0.7` 生成。该步惩罚后候选大致为代码围栏 67.44%、JSON 开头 23.10%、工具标记 9.46%。该概率由 BF16 target logits、当前惩罚及温度/top-k/top-p重建，仅用于这个样本，不能当总体误调用率。这说明正确的阶段切换并不保证遵守“不要调用工具”的语义要求。

最终候选另修正屏障不得把已耗尽的许可预算抬升为 1。完整程序重新链接通过；最终 SHA-256 为 `db3c7aca4efddea0cb504323cf0f2181514121603b875e26e1b5402010eff42f`。在原模板、原参数下再测十个短样本，仍为 8/10；98K 最终答案及旧失败历史纠正均为 10/10，三轮工具调用/结果共六请求全部正确。先完成连续工具续接再测旧失败分支，六请求均命中 100,837–101,368 tokens，整轮约 0.95–1.90 秒；旧失败分支缓存为 0，重读约 164 秒、整轮约 173 秒后正确回答。两次长测成功使用相同夹具，不构成独立质量统计。

**候选尚未安装，日常引擎及唯一回滚备份未变；不宣称循环已根治。** 群友超时仅记录，未改客户端看门狗。未执行满 256K、真实 dsh/浏览器全链路或其他模型/设备验收。测试服务已停止，未提交、推送或发布。脱敏[完整结果](../benchmarks/evidence/long-context-tool-loop/verification.json)保留通过与失败；私有原始流和维护脚本在 `runtime/long-context-loop/`。

## 短任务追加排查：冷启动与缓存路径

在最终候选和原模板下追加 12 次短请求，全部自然结束，没有请求错误或页池耗尽；这些是重复诊断，不是 12 个独立质量样本。没有修改生产源码、采样预设或日常引擎。

| 临时对照 | 结果 | 缓存与输出 |
|---|---|---|
| 原参数，`short-2` 连续重试并穿插 `short-3` | 1/4 通过 | `short-2` 冷启动正确，命中 813 tokens 后两次均误调用；穿插请求未改变热缓存结果 |
| 两阶段临时贪心，`short-2` 三次 | 1/3 通过 | 冷启动正确，两个热请求误调用且输出一致；温度归零没有解决 |
| 仅增加早期 logits 日志的探针 | 1/2 通过 | 重现原候选的冷成功、热失败；思考与正文和对应普通候选相同 |
| 临时关闭全部草拟 | 3/3 通过 | 同 seed 的冷、热 `short-2` 思考及正文逐字相同；`short-3` 也通过。另一次已有的无草拟贪心失败仍然有效，不能据此把关闭草拟当作通用修复 |

探针中，最初 36 个解码位置的 target 前 20 项 logits 完全相同。绝对解码位置 853 的草拟 token 首先不同：冷路径提议 id=1 后被纠正为 1149，热路径提议 1149 并被接受。当时 target 截断后两者概率约为 8.51% 与 91.49%，接受随机值约 0.544，两个决策均符合算法。

下一位置 854，冷路径是新一轮接受分支，热路径是上一轮 bonus 分支；target 分别在不同验证列求值，最高分相差约 0.125，且使用不同 purpose 的随机值，因此输出首次不同。独立 Python 重建 SplitMix64 与 top-k/top-p 分类采样，853/854 两位置共四个决策全部吻合。这里核对的是局部采样决策，不是完整词表、全部缓存或整模型 MTP 状态等价证明；最初草拟差异仍需更细的状态/数值对照才能归因。

这排除了“同 seed 输出不同就一定是随机状态残留”的推断，也没有找到足以据此追加生产补丁的具体缺陷。**短任务误调用尚未修好，原候选继续保留为未安装状态。** 关闭草拟会使本组 decode 由约 100 tokens/s 降至约 43 tokens/s，但输出序列不同，此数值不是受控性能基准；日常配置没有关闭草拟。

本轮 13 个临时探针/重复测试 exe 已清理，释放约 16.18 GiB；本任务只保留最终候选 exe、源码、日志及必要构建对象。正式 exe 和唯一回滚备份的哈希复核未变，清单保存在本地 `runtime/long-context-loop/cleanup-manifest.json`。

上述短任务追加排查另建的日志探针也在结束后删除，保留脚本、对象和证据；单独清单为 `runtime/long-context-loop/cache-followup-cleanup.json`。
