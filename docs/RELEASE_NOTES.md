# v0.1.3 — NVFP4 KV、5070 Ti Laptop 长输入优化与累计缓存压力修复

发布维护者当前使用的引擎：默认 KV 从 RK4V4 切换为 NVFP4，增加 RTX 5070 Ti Laptop 的 prompt attention 调度，修复累计缓存后 Host KV 压力无法正确回收而导致的页池耗尽。保留 v0.1.1 / v0.1.2 的检索上下文、已提交生成历史索引、缓存问句保护和小矩阵调度。

**显存提示：当前 NVFP4 配置相对此前 RK4V4 增加了一些显存占用。显存很紧张时，可在 `config/local.json` 添加或修改 `"KVDType": "rk4v4"`，正常停止本安装后重启。** 同一新版引擎支持两种 KV，无需换回旧 exe；NVFP4 专用 prompt 优化只在 NVFP4 下生效。切换后重新建立 GPU/Host 缓存，磁盘会话与权重保留。显存差值随页池、工作区、Graph 和其他程序变化，不承诺固定 MiB 数字。

特别感谢 Bilibili [0xFFFF7](https://search.bilibili.com/upuser?keyword=0xFFFF7) 提供基础分享版本并解决此前的死循环问题；保留 NInfer、KVMem、Qwen、ISTA-DASLab 及其他上下游的归属和许可。

## 本版改动

- **NVFP4 prompt 调度：** 仅 cc12.0 / 46 SM 自动选择 8 warp、成对 FP16 解码和全屏蔽页跳过；保留原 NVFP4 编码、BF16 QK、FP16 PV、FP32 累加与兼容内核，不新增常驻 GPU 工作区。稀疏跳页可能产生浮点尾差，不承诺逐位相同。启动前 `NINFER_NVFP4_SM120=0` 可关闭专用调度，仍使用 NVFP4 KV。
- **Host 重复副本回收：** Host 满且无法继续换出时，释放已有有效 Device 副本的完整页之 Host 副本；保护固定源页、部分尾页、事务和仍在进行的 H2D。
- **Host-only 闲置缓存回收：** 扣除可用页、Host 空间和重复副本后仍不足原 ring 缓冲，才将具有独占 Host 字节的闲置 owner 纳入原 LRU。活动历史、共享引用与活跃复用边受保护。旧缓存被淘汰后重访需重算；高压力下同步与搬运可能增加。
- **部署配置：** `KVDType` 支持 `nvfp4` / `rk4v4`；新配置和缺少该字段的旧配置均默认 NVFP4。公开页预算仍为 DeviceKV 36864 / RetrieveTokens 3840，不自动提高到维护者的 39168 / 6144。

## 实测与边界

RTX 5070 Ti Laptop 12GB / 46 SM，CUDA 13.0.48、MSVC 14.44.35207。下列新测试使用维护者的 Huihui Qwen3.8-27B Swift-1.5 GSQ-RCO IQ3_XXS + MTP 制品，NVFP4、xhigh、原采样、MTP3、chunk128、256K 逻辑容量、DeviceKV39168 / Retrieve6144 / HostKV7168MiB。它与旧版 GSQ-RCO 夹具不能直接比较为量化质量收益。

| 测量范围 | 结果 |
|---|---|
| 单轮 128K / 200K 冷输入，兼容路径对专用调度 | prompt 耗时减少 18.86% / 26.66%，两路径召回均 10/10；不等于 decode 同比提速 |
| 同一最终 exe，从新进程关闭 / 开启调度，206552-token 长任务 | 512 行、六工具和 18/18 召回均通过；prompt 683.215 → 359.219 s；单轮结果不承诺通用倍率 |
| 最终 exe 短前缀，两 seed，关/开/开/关，共八请求 | 同 seed 含思考输出哈希和 MTP 接受数一致；加权 decode 78.264 / 78.116 tok/s（-0.19%），没有显示明显直接解码退步 |
| 累计四次 128K / 200K 冷暖召回后接长任务 | 修复前 375/512 行后 HTTP 500；完整修复后一次完成 512 行、六工具、最终 18/18；回收 41 页重复副本、1 个闲置 owner |
| 原生验证 | 独立 NVFP4 数值 / Graph oracle、页存储 / 异步恢复检查、资源管理器 76 项通过 |

首次页池失败记录保留；完整 v2 经过重新编译，不能写成全部同一二进制的开关对照。测试为固定 seed 的合成 API 任务；没有证明 NVFP4 总体质量优于 RK4V4，未测满 256K、多 seed 能力、其他 GPU 或完整 dsh / 浏览器链路。压力修复不扩充物理容量，真实容量不足仍可能失败。

构建为受影响 CUDA / Host 单元增量重编并复用其余原静态库，未完成干净全量构建或全部上游测试。本版没有合入最近只读评估的 NInfer 上游修复；本机 dsh 的有限提前结束续写插件也不在此包中，直连引擎保留原 EOS 行为。

## 下载与升级

使用 v0.1.3 的 Source code ZIP 或更新后的仓库，执行 `setup.ps1 -ModelPath "<现有模型.ninfer>"`。已有安装先完成任务并用本安装 `stop.cmd` 关闭，保留配置、会话和权重，更新源码后重跑安装器。只拉取源码不会替换已经下载的 exe。已有配置缺少 `KVDType` 时升级启动将采用 NVFP4；希望维持 RK4V4 的使用者应先显式添加该字段。v0.1.0 / v0.1.1 / v0.1.2 资产保留供回滚。

先从完整保守组合 36864 / 3840 起步并验证短任务、缓存、工具续接及目标长度召回。旧 RK4V4 的约 84 MiB CUDA 余量是历史记录；当前 NVFP4 进阶档启动日志约 64 MiB。它们不是控制变量下测出的固定差值，驱动整卡空闲也不等于 CUDA 可分配余量。显存很紧张可切回 RK4V4；不要只缩小页池却保留装不下的窗口。

引擎 ZIP 仅含程序、许可和来源说明，安装器获取固定哈希的 cuBLAS / LGPL FFmpeg；不含权重、DLL、SDK、用户配置、私有日志或登录凭据。Windows x64 / sm120a，需 CUDA 13 兼容驱动及 VC++ x64 运行库；dsh 需 Node.js24+。
