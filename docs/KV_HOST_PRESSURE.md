## 修复设计

检索从 Host 恢复页面后，会同时保留 Device 与 Host 副本。旧 ring 路径只尝试 Device → Host 换出；Host 满时，尽管有可删除的重复副本，也会停止换出，随后无法映射新页。

`storage/ring_host_pressure.h` 在执行边界回收有有效 Device 副本的完整页之 Host 副本，保持逻辑页面、地址引用、检查点、旧缓存、Device 映射及历史内容。优先回收较新的驻留页，避免刚释放又换出同一页；每次至少尝试 64 页以分摊同步成本。固定源页和未写满尾页跳过，共享页面去重。释放前等待各 rank 的 compute stream，保护仍在读取 Host 的 ring H2D；有上下文事务时不回收。

此路径仅在 Host 连一个新页都分配不出、ring 换出仍未腾足空间时进入。启动前设置 `NINFER_KV_HOST_DUPLICATE_RECLAIM=0` 可作为旧行为对照。它不改变 NVFP4 数学、权重、采样、xhigh、逻辑上下文、Device/Host 预算、检索选择或缓存保留策略，也不新增常驻 GPU buffer。

第一版整模型对照精确复现 375 行失败；只启用重复副本回收后，释放 41 个主模型 Host 重复副本，一次完成 512 行，第一个工具成功，但第二个工具仍耗尽页池。此时已没有可回收的重复副本，继续保留独立的两段长历史确实达到总容量上限。

第二版在 decode 边界补上 Host 压力通知：按 ring 既有八页缓冲计算需求，扣除 Host 空间、空闲 Device 页和可回收重复副本后仍有缺口，才沿原来的 private/shared 最近最少使用顺序处理闲置缓存。原流程只接收 Device 缺页，因而漏掉完全位于 Host 的旧缓存。现在使用 owner 的独占 Host 字节，跳过活跃复用边、事务、共享给其他地址的页，以及原有受保护 shared owner；由资源管理器正规释放、同步目录与引用。活动历史和客户端消息不裁剪，闲置旧缓存淘汰后再次访问需重读。`NINFER_KV_HOST_PRESSURE_RECLAIM=0` 可关闭这层处理作诊断对照。

这不是容量扩充：如果没有可回收的重复副本，或逻辑历史确实超过总容量，仍可能失败；本修复不声称覆盖所有资源耗尽、碎片或并发情况。

## 验证

独立 `ninfer_qwen3_5_ring_host_pressure_test` 构造两级全满、旧缓存完全在 Host 的场景：旧换出失败，回收重复副本后能换出并映射新页。检查固定源页、部分尾页、旧缓存、历史 frontier、分裂后的 extent 和字节内容；另检查恢复后立即回收时的异步 H2D 保护。已有 `ninfer_qwen3_5_context_store_test` 覆盖共享前缀、尾页 COW、extent 分裂及资源归还。

本机独立存储回归均通过；资源管理器76项检查全部通过。整模型保持NVFP4、xhigh、采样、MTP3、256K逻辑上下文、39168 Device KV、7168 MiB Host KV及原检索预算。连续运行四次128K/200K冷暖召回，再接206552-token长任务、六次合成工具往返与18字段召回。前置请求及长输出请求JSON相同。
