# DSH 模型流空闲超时排查记录（2026-10-20）

群友截图显示 `pi-ai stream idle timeout after 300000ms`、重试 `(2/5)` 和重试延迟 `1073 毫秒`。本次仅只读排查，未取得群友引擎/客户端日志，未复现，未修改超时或心跳。

核对 npm 发布的 `@deepseek-ai/dsh-llm-pi-ai`、`dsh-timeout`、`dsh-llm`、`dsh-llm-retry` 的 `0.2.1-rc.2` 包：适配层对转换后的模型事件迭代器使用 300000ms idle watchdog；正文、思考、工具调用事件可以推进迭代，`start` 被忽略。SSE 注释保活不是这些模型事件。默认 TIMEOUT 可重试，最多额外重试 5 次。1073ms 是再次发请求前的退避，不能当作失败请求的耗时。截图中的版本文字尚不能代替群友实际安装清单。

当前本地引擎 Chat SSE 有约 5 秒间隔的 `: keep-alive` 注释机制，但这不能直接重置上述模型事件计时器。工具调用在生成完成后由 `OpenAIChatStream::finish` 发送；大量预填充、排队或长工具参数生成可能没有客户端认可的输出。普通持续思考的 reasoning delta 会推进计时，不能仅因 xhigh 就断言必然超时。

本机先前 98,592-token 冷输入的预填充分别为 237.179s / 240.641s。这说明更长或更慢的冷读可能接近或超过客户端 300s 门槛，不证明群友此次就是缓存失效、NVFP4 或引擎故障。正常前几步也不能保证下一次模型请求的长度和缓存命中不变。

待核对：群友实际模型/引擎哈希、DSH/适配器版本、连接地址与代理链；故障前后约 10 分钟的服务端与客户端日志。区分预填充是否继续推进、缓存命中、排队、取消，以及 CUDA/页池/断连错误。保留为待定位问题，不以单纯加心跳或无限放宽超时作为已验证修复。
