# 工具解析器原有 9 项失败：原因与修复（2026-10-20）

第一批工具输出恢复验收时，原版和候选均存在 8 个解析器测试、1 个前端测试失败。
进一步核对表明，主要是基础分享包两处历史补丁改变了行为，测试保留了原本的约束；不能仅把这些失败归为测试过时。

## 逐项原因

| 测试 | 旧版实际行为与原因 | 本轮处理 |
|---|---|---|
| `test_forced_call_decoder` | 强制调用参数停在 `</par`，第三次“抢救”仍追加函数/封套结束标签，返回原工具和半截参数 | 不补未知边界；返回带原工具名的错误回执 |
| `test_unrepresentable_parameter_delimiters_are_reported` | 参数文本包含结构性的闭合标签时，抢救逻辑在首个函数闭合处截短，可能把命令 `echo…tail` 变成 `echo` | 不截短后重试解析；歧义调用返回错误 |
| `test_recovery_of_strict_failures` | 只有函数开头也被补成空参数的正常调用；随后测试读取不存在的 `error` 字段，未捕获异常导致测试进程退出 | 修正调用恢复，并让测试只在确为错误回执时读取字段；原断言保留 |
| `test_partial_region_keeps_complete_calls` | 完整第一调用后，截断第二调用也被补成正常调用 | 第一调用保留，第二调用返回错误 |
| `test_marker_attempts_are_bounded` | 16 次候选上限仍有效，但耗尽后仅凭最早的 `<tool_call>` 就进入错误调用路径，原文丢失；不是第 17 个候选真的被执行 | 没有打开函数的标签说明保持原文，上限不变 |
| `test_later_candidate_must_consume_the_end` | 引用标记后的调用示例并未消费到输出末尾，本应整段为文字，却被最早的封套标记误报成错误调用 | 函数没有在该位置开始时保持原文，不从说明里挑取后续调用 |
| `test_incremental_fallback_preserves_bytes` | 同时涉及半截函数被补成正常调用，以及纯标签说明被拦截、字节丢失 | 分别修正上述两条路径，流式与整段一致 |
| `test_harness_forms_recovery_and_streaming` | `<invoke>` 形式走同一抢救代码，第二个截断调用也会被补成正常调用 | 完整调用保留，截断调用返回错误，保持流式一致 |
| `test_forced_tool_call` | 前端实际输出会话重现了第一项：未完成参数被转成强制工具调用 | 同一解析器修复在前端层通过验证 |

旧版 `3221226505` 退出发生在第三项的测试进程内。它不是这轮发现的真实模型服务崩溃；没有证据表明 NVFP4、显存页池或 CUDA 内核参与了这些失败。

## 实现与行为边界

移除 strict 和 lenient 两次解析均失败后的第三次猜测式修补：不再合成函数结束边界，也不截短参数去追求解析成功。
对普通文字的分流只在真实函数开头出现时拦截，不再仅凭 `<tool_call>`。具有 `name=` 属性但引号不闭合的函数仍作为格式错误报告，不能回退成普通说明。

保留原有边界明确的修复：真实 `</function>` 能界定未闭合参数、只缺最外层 `</tool_call>`、重复参数取最后值、正文中多余参数闭合标签，以及错误之前已完成的并行调用。
第一批 Markdown 保护与严格的未闭合思考恢复也保留。没有更改 KV、CUDA、MTP、采样或页预算。

取舍是：半截写文件/命令不再被“抢救”为可执行调用，客户端收到 `malformed_tool_call` 错误后需要重试或拆分。
这可能多一轮生成，也可能使以前勉强返回的截断输出明确失败；不会自动补出模型尚未生成的内容。
真实模型的一次错误后重试通过，不代表所有客户端、长输出额度和重试循环均已覆盖。

## 验证

原有 9 项均通过。完整解析器组从 30/38 变为 39/39（新增 1 项跨切块边界回归），完整前端组从 53/54 变为 54/54。
除了按函数独立运行，也直接执行了两个完整测试程序，均退出 0；第一批 Markdown、开放思考、取消和限长检查包含在其中。
新增检查覆盖 1/2/7 字节及整段切块、半截正文和结束标签、空函数开头、损坏的名称属性，以及需要保留的三类明确边界容错。

构建仅重编工具解析器一个 Host 单元，再链接第一批已验证的对象和原静态库；不是干净全量构建，也没有重跑全项目 CTest。
真实模型保持原路径、NVFP4、xhigh、MTP3 及 39168/6144 预算，通过短工具/结果、49452-token 召回（10/10）、长历史工具/结果和 Markdown 示例检查。
后两轮命中 50402 / 50484 tokens，只预填充 27 / 53 tokens，整轮约 1.01 / 1.36 秒。
另以强制工具 API 的既有无思考路径、单请求 4-token 额度刻意制造截断，确认返回错误而没有返回真实工具；错误反馈后，模型下一轮正确重试。
API 的该次 finish reason 为 `tool_calls`，底层诊断记录 `output_limit`，不能仅凭 API finish reason 认定输出完整。
本轮没有改变服务默认 xhigh；上述单请求是强制调用接口验收。

22 次约 5 秒间隔的显存采样，最高已用 11180 MiB、最低空闲 765 MiB，仅是 WDDM 下 `nvidia-smi` 观察值，不是 CUDA 可分配余量。
第一批 205124-token 结果仍属于其当时的引擎，不充当本轮新程序的重复实测；未执行满 256K、多 seed 或完整 dsh/浏览器链路。
