# 短任务误调用：回答阶段 presence penalty 诊断

日期：2026-10-21。延续 [FP16 GDN 一致性与换模型对照](GDN_FP16_CONSISTENCY.md)。本轮只做参数实验和私有日志诊断，没有新增生产源码补丁、替换日常引擎或修改默认采样。逐项脱敏结果见 [answer-penalty-diagnosis.json](../benchmarks/evidence/long-context-tool-loop/answer-penalty-diagnosis.json)。

已确认一个影响因素：思考阶段生成的 token 计数保留到回答阶段；回答的 presence penalty 会压低思考中出现过的 JSON/代码围栏开头，相对提高此前未出现的工具标记概率。仅取消回答阶段惩罚，在本夹具上减少了误调用，但仍有失败。现有证据不能把剩余问题确定为模型、量化或前向实现中的某一方。

## 配对参数实验

使用未安装的 FP16 GDN 候选 `153f562272c10e603e84cfd9d5bbf9ceb296270139dad52708ac96f8ecd4a808`。两种模型各运行同一道 818-token 合成短任务，seed 为 20359323–20359332，首轮冷启动、其余请求复用 813 tokens。只有最终正文十项均正确且没有实际工具调用才通过，思考里算对不计成功。

唯一请求覆盖为 `"post_thinking":{"presence_penalty":0.0}`，对照值为 1.0。保留思考采样、xhigh、原模板、权重、NVFP4、FP16 GDN、MTP3/ngram15、262144 上下文上限及页池/检索预算。两组请求逐 seed 核对，除该覆盖外完全一致；两个模型各十个思考文本前后均逐字相同。

| 模型 | 回答 presence=1.0 | 回答 presence=0.0 |
| --- | --- | --- |
| Huihui Swift 1.5 GSQ-RCO IQ3_XXS | 9/10 | 10/10 |
| 非 Huihui GSQ-RCO IQ3_XXS | 7/10 | 9/10 |

这是每个模型同一道题的十 seed 对照，不是十类独立任务，也不是总体质量提升比例。Huihui 基线只取 `short-0` 至 `short-9`，不混入后来追加的两次热缓存重复。该干预没有在已安装日常 `b1f832…` 上另跑十 seed，不能将本表写作日常引擎新默认的验收。

## 惩罚怎样改变候选排序

`engine/src/models/qwen3_5/program/program.h` 的 `update_sampling` 契约明确规定 penalty counts carry over；`program/decode.cpp` 更新回答采样时保留已有计数。`engine/src/ops/kernel/sampling_device.cuh` 对出现过的 token 扣 presence penalty，再执行温度和候选筛选。presence 惩罚按是否出现计算，不因出现两次而扣两倍。

私有日志探针在同一候选上仅覆盖三个 Host 日志单元，CUDA 对象不变，记录真实渲染输入、思考边界、送入解析器前的原始输出，以及回答前八步完整 BF16 logits 和 I32 计数。正式源文件未改。以下是非 Huihui GSQ 的失败位置：

| 局部位置 | 实际回答 presence=1.0 的概率 | 相同原始 logits 改 presence=0.0 的概率 |
| --- | --- | --- |
| 关闭投机，short-0 首回答 token | 代码围栏 39.01%，工具标记 32.63% | 代码围栏 70.43%，工具标记 14.12% |
| 关闭投机，short-1 首回答 token | 工具标记 65.50%，左花括号 26.82% | 左花括号 60.46%，工具标记 35.39% |

第二例中，左花括号原始 logit 为 24.125、计数为 1；工具标记原始 logit 为 23.75、计数为 0。扣除 1.0 后，原本更高的左花括号被工具标记超过。实际随机抽样与独立 CPU FP64 重算吻合。

这些同 logits 的概率是单个位置的反事实计算，不是完整替代生成轨迹；不能据此承诺某个随机数在另一条轨迹中一定选对。完整轨迹改善的证据来自前述独立配对请求。

仍失败的 GSQ `short-0` 在保留 MTP、回答 presence=0 时，工具标记的原始 logit 已经最高：23.375，对应概率 59.57%；左花括号为 22.75、24.39%，代码围栏为 22.25、11.94%。该步 CPU 重算也选择工具标记。因此取消回答惩罚不足以根治误调用；未用独立前向实现验证这些原始 logits，不能直接判定为纯模型问题。

## 对采样、计数、模板与解析器的核对

- 普通无投机探针两个请求共 16/16 个位置的选择与独立 CPU FP64 重算一致；官方模板复跑也为 16/16。保留 MTP、回答惩罚为零的两个请求，16/16 个 target 选择与 CPU 耦合抽样重算一致。这验证的是给定已捕获 logits 与计数后的局部抽样，不是完整前向正确性证明。
- 从 SSE reasoning token 字节及明确记录的思考关闭、分隔 token 独立重建完整 248077-token 词表计数。冷 `short-0` 为 871+2=873 tokens，热 `short-1` 为 647+2=649 tokens，与 GPU 计数数组均为零差异。这两个位置没有上一请求计数残留的证据。
- 使用本机原始 tokenizer_config 官方模板复跑两个无投机请求。实际渲染输入逐字一致，均为 2963 bytes，SHA-256 为 `69a7fad34748c5eb69cad3abb09b4e6596896070b8e2bf1a5242ddb3a4384dfe`；16 组完整 logits/计数数组逐字一致，输出忽略随机调用 id 后一致。只对这两个夹具成立，不能覆盖模板全部功能。
- 思考关闭 token 248069、随后双换行 token 271 正常，回答温度为 0.7。失败请求在进入工具解析器前已经生成完整工具 XML；不是解析器把正确正文转换成工具调用。

## 不同功能与长上下文验证

Huihui 在回答惩罚 1.0 和 0.0 下各通过 12/12 步。范围为六类直接任务：算术、中文字段提取、JSON 转义、两行 Python 函数、筛选求和、撤销先前工具计划；另有三次显式工具调用及三次工具结果回答，包含合法重复读取和不可信工具文字。不是十二类任务。十二个思考文本前后均相同，请求语义除惩罚覆盖与调用 id 外一致。

Huihui 同候选、回答 presence=0 的长任务组为 7/7：98,592-token 冷输入的最终十项答案全对，随后三次显式调用和三次结果回答均正确，包含再次读取同一记录；六次续接命中 100329–100819 tokens，整轮约 1.09–1.44 秒。冷主任务约 256.98 秒，引擎报告生成约 93.95 token/s，仅为本轮观测，没有受控速度对照。未出现循环、页池耗尽或 CUDA 异常。本轮没有追加旧失败历史纠正轮，不与此前的 8/8 混算。

## 剩余边界与后续方向

尝试获取官方 llama.cpp b11784 CPU 工具，以同权重做独立前向交叉验证；固定资产下载在有界网络尝试中未完成，已停止重试。没有校验通过、解压、运行或安装该工具，也没有独立前向结论。共享模型家族、IQ3_XXS 权重量化及 NInfer 前向路径仍需区分。

关闭回答 presence 可能增加长正文或代码重复。当前 98K 召回与短工具续接不能覆盖长自由生成的这项代价，因此没有把零惩罚设为日常默认。后续应先完成独立前向或更高精度权重对照，再决定是否需要改底层或设计显式的分阶段惩罚范围；不能把现有 carry-over 契约直接标成 CUDA bug。

后续已完成[回答阶段独立计数原型试验](ANSWER_PENALTY_SCOPE.md)：不再携带思考计数，保留回答内presence=1。短同题收益与零惩罚相同，功能组没有新增失败；补测代码、重复字段JSON、正文结构及98K续接。正文仍有事实性错误，部分边界仍误调用，独立前向尚未完成；候选未安装，不能视作最终修复。该后续报告同时更正前轮功能组的模型标签：原12/12是Huihui，GSQ三种策略补测均11/12，十seed主表不受影响。

没有执行满 256K、真实 dsh/浏览器任务、其他设备测试或受控性能比较。未以禁用工具、缩短思考、删历史或强制结束来计作成功。
