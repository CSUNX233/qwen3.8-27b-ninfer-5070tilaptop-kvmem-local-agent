日期：2026-10-21。本地候选 SHA-256：`153f562272c10e603e84cfd9d5bbf9ceb296270139dad52708ac96f8ecd4a808`。
基于日常试用的 `b1f832…`，尚未替换日常引擎。脱敏证据见
[gdn-fp16-verification.json](../benchmarks/evidence/long-context-tool-loop/gdn-fp16-verification.json)。

## 已确认的缺陷

本机启用 `--gdn-state-fp16`。普通单 token 解码从 FP16 状态读取，以 FP32 更新并计算当前输出，随后把状态舍入为 FP16，供下一 token 使用。
原 ReplaySSM record/fold 把一组 token 的状态持续保存在 FP32 寄存器中，跳过中间的 FP16 存储舍入；fold 只在批末写回时舍入。
因此即使给定完全相同的 Q/K/V、gate、初始状态和 token 前缀，验证输出与提交状态仍不等于普通逐 token 解码。

补入 FP16 后，旧对象的 record 关系检查 26/26 不一致，fold 的 62 个案例中 34 个不一致。
旧测试仅覆盖 FP32 的 record/fold 关系，单独的 FP16 长链误差测试不能检测这项跨路径契约。
这确认了一个数值一致性缺陷，尚不能把所有误调用、短任务失败或长上下文循环归因于它。

## 最小实现

修改 `engine/src/ops/linear_attention/gated_delta_net/recurrent.cuh`：record 在当前 token 的未舍入状态完成输出后，用 FP16 round-to-nearest-even 舍入寄存器状态；fold 对每个已提交 token 执行相同舍入。
使用 half2 转换后立即扩展为 FP32，后续乘加继续采用 FP32。处理跨内部 16-column stage 的连续状态，保持零提交为 no-op。

普通 decode、多 token prefill、FP32 路径及卷积历史算法保持原执行方式。没有新增 GPU buffer 或状态副本；权重、KV NVFP4、原模板、xhigh、两阶段采样、MTP3/ngram15、262144 上限和页池/检索预算保持原值。
修复会改变 FP16 投机路径的 logits、接受率及输出文本；逐 token 舍入增加转换指令，性能需要实测。

## 验证范围

- record 共 252 个关系案例，包含新增的 26 个 FP16 案例，均通过。FP16 同时使用独立 scalar FP64 递归 oracle 检查第一行第一 value head 的输出；逐位 GPU 对照覆盖全部有效输出、源状态、原始记录、masked 后缀及 CUDA Graph。
- FP16 fold 的 62 个案例均通过，覆盖 Hv32/48、宽度 2/4/16/17/32/64、部分/零/全提交、独立/原地目标、多行、按 64 列规划后以较窄实际宽度打包及 Graph。
- 完整 fold 程序通过，保留原 FP32 检查及宽度 16/32 的多轮 record-fold 耦合检查。
- 独立 FP64 GDN 正确性程序通过；FP16 状态长链以每次 1/4 token 分别执行 4096 tokens，两次均通过。这些长链使用一般 GDN Op，不能单独证明完整模型投机路径等价。
- 原日常十 seed 短测复现 9/10，`short-8` 误调用。候选仍为 9/10：`short-8` 及其热缓存重复通过，但 `short-6` 误调用。额外 `short-2` 热缓存重复通过。工具始终可用，只按最终正文及实际调用评分。
- Huihui 候选关闭 MTP 和 n-gram 的诊断 3/3 通过：`short-6` 冷/热结果逐字一致，`short-8` 热缓存通过。仅覆盖两个 seed；关闭草拟会显著降低生成速度，不作为生产修复，也不能证明所有短任务误调用都来自投机路径。
- 长任务组 8/8 通过：98,592-token 冷输入最终答案10/10，三轮显式工具调用和结果续接全部正确，含再次合法读取同一记录；缓存命中100,229–100,727 tokens，六次续接约0.92–1.42秒。旧失败历史纠正轮100,634-token输入、缓存为0，重读约164.6秒后最终答案10/10。没有出现页池耗尽、循环或异常退出。这些复用既有合成任务，不是新八类任务质量统计。

短测来自同一个合成任务的十个 seed，不能当作十类独立任务，更不能据某个 seed 通过宣称总体质量提高。
初步相同输入 Op 性能 A/B/B/A 的末轮基线延迟明显漂移，不能作为受控提速或减速结论。

GSQ 候选另起服务复跑 `short-0/1/1/6`，4/4 再现误调用，思考文本、正文和调用函数/参数与原轮逐字相同（忽略每次新建的调用 id）。同样顺序、同一候选仅关闭 MTP/n-gram 后为 1/4 通过：冷 `short-0` 及两次热 `short-1` 仍误调用，热 `short-6` 通过。因此剩余失败不依赖投机解码，不能用关闭投机作为通用解决办法；也不能将 Huihui 关闭投机时的 3/3 通过外推到另一模型。这是选取失败 seed 的诊断，不与十 seed 主比较混算。

同一模型家族、权重量化族、模板和推理实现仍是共同变量；十 seed 也都来自同一道任务。不能仅凭该对照认定全部责任属于模型或引擎，也不能把候选的 5/10→7/10 外推为整体质量提升。没有用独立推理实现或更高精度权重交叉验证。脱敏逐项结果见 [short-model-comparison.json](../benchmarks/evidence/long-context-tool-loop/short-model-comparison.json)。
