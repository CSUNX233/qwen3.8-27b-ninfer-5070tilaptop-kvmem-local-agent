# C2.1 移植到 v0.1.4：本地验证记录

2026-10-24。本轮将 C2.1 的长锚点恢复和 KV 批量回迁移植到 **v0.1.4**，先作为本机日常试用候选完成验证，现将同一二进制整理为v0.1.5发布。本页保留实际验证条件；发布入口见[更新说明](RELEASE_NOTES.md)。

## 基线与保留内容

源码基线为 `v0.1.4` / `4e4ee4262f333b75b4d94afdf41d31d2c1f4e500`，工作分支为 `codex/v015-c2p1-v014`。没有用本地停在 v0.1.3 的 `main` 分支作为构建源。

保留 v0.1.4 的工具输出解析及容错边界、思考闭合屏障、耦合采样、NVFP4 验证列分区与 FP16 GDN 舍入一致性，以及回答阶段独立惩罚计数。部署继续使用 `AnswerPenaltyScope=answer`；模型、NVFP4、MTP3、xhigh、采样值、GPU/Host KV 预算和 CPU 视觉配置均沿用本机日常设置。

历史版本归属更正：切换 C2.1 前的日常引擎为已发布 v0.1.4 对应二进制。旧 C2/C2.1 实验链使用既有本地工作目录逐步叠加修复，其中已经包含多项 v0.1.4 修改，不能将其概括为纯 v0.1.2；同时，它也不是从干净 v0.1.4 标签统一重建的候选。旧源码快照相似度不能证明旧二进制每个链接输入的版本归属。本轮改为以明确的 v0.1.4 提交重编 Host 覆盖单元，并记录所有复用链接输入；构建范围及限制见下文。

## 本轮移植

- `NINFER_C2_ROLLING_ANCHOR=1`：补充可在追加消息时执行的近尾消息边界长锚点；按间距节流自动捕获，并保留有用的早期回退锚点。显式标记不受自动节流限制。
- `NINFER_C2_CONSUME_ANCHOR=1`：同一 lineage 从长锚点恢复时，允许消费原活动 owner，并保留可复用的不可变状态和 KV。不同 named session、只读请求继续保留原来源；不将私有锚点提升为共享缓存。
- `NINFER_KV_DEMOTE_BATCH=32`：将 eligible 冷页分批回迁到 Host，减少独立 D2H 传输批次。缺省为 1，范围限制在 1～64；大 Host extent 分配失败时缩小批次，最终回退到单页，允许在有限空间内部分推进。

回迁保持原先的 oldest-first、sink、preferred-page、source-pin 和部分尾页约束，当前 Host 副本可直接复用。未修改注意力公式、量化格式或检索窗口，也未启用 materialization 调试探针。

## 实际构建方式

CUDA 13.0.48 / MSVC 14.44.35207 / `sm120a`。71 个既有 Host 覆盖编译单元全部从上述 v0.1.4 工作树重新编译；复用 11 个已验证 CUDA 对象及其余原静态库。**这是增量构建，未完成干净全量 CUDA 构建。** 本机记录了生产源码、Host 对象、复用链接输入和最终二进制的 SHA-256。

## 本轮验证

12 项定向回归均通过：rolling-anchor、完整 frontend、完整工具解析器、materialization budget、resource manager、sampling defaults、batch32/batch1 回迁、累计 Host 压力、context store、KV cache、真实模型恢复与隔离。

恢复夹具覆盖冷启动贪心 token 一致性及首 token logprob 对照、12 次分支改写、不同 named session、只读复用、准入后取消和后续恢复。回迁测试逐字节核对 Host/Device 往返 payload，并验证紧张 Host 空间下的部分推进及重复副本不再传输。20 页在 batch32 下为 1 次复制批次，batch1 下为 20 次；这是该夹具的传输次数，不能直接换算为整模型加速倍数。

使用相同日常模型和完整 KV 预算，重跑恰好两个多轮长上下文夹具，各 7 个请求：

| 任务 | 压缩前 | 压缩后 | 压缩后复用 | 压缩后请求耗时 |
|---|---|---|---:|---:|
| 藏针，最高 68,358-token 输入 | 7/7 字段正确 | 7/7 字段正确 | 58,330 tokens | 1.93 秒 |
| 小游戏状态与代码续接，最高 68,540-token 输入 | 6/6 字段、6/6 代码运行检查 | 6/6 字段、6/6 代码运行检查 | 58,459 tokens | 2.77 秒 |

14 个请求的输出 token 序列与原 C2.1 同夹具贪心结果全部一致。两个进程总耗时约 153/156 秒，包含首次长输入预填充；上表仅为最后一次压缩后请求，不能当作整项任务总耗时。每 5 秒采样的 GPU 已用显存峰值分别为 11,176/11,174 MiB，不排除采样间瞬时峰值。

旧 C2.1 的同组藏针/续接记录也分别为 11,176/11,174 MiB，因此本次移植前后在这些采样中未观察到显存峰值增加。这是整卡已用显存，包含其他进程占用，不是引擎独占分配量。尚无原版 v0.1.4 在相同模型、配置、任务和后台条件下的对照记录，不能据此声称相对原版增加 0 MiB，也不使用其他版本或不同任务的峰值相减。固定 Device KV 预算未扩大，长锚点主要使用有界 Host 内存。

长任务为 thinking-off、greedy 合成夹具，代码通过 Node 黑盒检查；不是完整浏览器小游戏开发或长时间 xhigh Agent 验收。此前 C2.1 的其他项目测试也不计入本轮重新验证数量。未重跑全量 CTest、256K 满上下文、所有 GPU 架构或独立前向模型质量评测。

测试 helper 收入匿名命名空间，并补充无可用 CUDA 时返回 77 的跳过路径；仅重编该测试、重跑 batch32/batch1，两项均通过，生产 exe 未变。

替换日常并恢复标准启动后，经缓存守卫完成 7 个合成 HTTP 请求：首次文本、缓存命中文本、一次 xhigh 短算术、工具调用、工具结果续接、CPU 视觉识图、图片后的文字续接，均通过内容与完成状态断言。缓存命中文本复用 72 tokens，图片后文字续接复用 310 tokens；视觉测试正确识别左侧红圆和右侧蓝方块。这些检查覆盖 API 调用链，不等同于完整 dsh Agent 项目验收。

引擎健康端点返回 200。未登录访问 dsh 根页面返回 401，属于现有登录保护；最初脚本将它误判为健康检查失败，修正后重核现存 7 个响应并仅补查健康端点，没有重复生成请求或读取登录凭据。

## 本机切换与代价

通过长任务后替换日常 exe，安装时核对启动器、模板、惩罚范围配置和 DLL 哈希不变；原日常 C2.1 二进制及启动文件保存在本机维护目录，提供带校验的回退脚本。停止及恢复使用既有日常入口，不清理模型或磁盘会话。跨进程 GPU/RAM 缓存仍需重新建立。

自动长锚点会占用有界 Host 状态/KV 并在捕获时增加工作；批量回迁可能短暂等待更大的复制批次。内存压力下仍可回收锚点，不能保证所有请求命中，也不能保证所有上下文或任务都会更快。此处的字段正确与 token 一致性只支持这些夹具通过，不能据此声称模型总体质量提升或所有循环问题根治。

脱敏结果见 [verification.json](../benchmarks/evidence/c2p1-v014-port/verification.json)。完整构建输入与原始本轮合成日志仅保存在本机维护目录，不附带用户会话。

## 后续发布默认设置

后续 GitHub 更新和离线整合包默认仍为**纯文字 + MTP，不启用视觉**。继续使用文字模型制品、dsh 的 `text` 输入声明及不含 `--vision-cpu` 的默认启动参数；打包时核对模型组件，不能仅凭文件名判断是否包含视觉。视觉作为显式选配，不将维护者本机的 CPU 视觉配置自动带入发布包。本机当前 CPU 视觉设置保留。v0.1.5按此要求整理，详见[整合包说明](OFFLINE_BUNDLE.md)。
