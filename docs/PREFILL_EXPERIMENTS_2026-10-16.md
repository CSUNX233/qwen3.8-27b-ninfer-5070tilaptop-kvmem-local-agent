# 预填充实验：2026-10-16

本分支包含三个**缺省关闭、未部署**的实验。发布的 v0.1.2 包对应稳定引擎，不含这些实验；日常 exe 与启动配置的 SHA-256 在测试前后相同。没有因实验改变量化、检索、采样、xhigh、MTP 或上下文保留策略。

## 代码与适用范围

- `NINFER_INCREMENTAL_LEXICAL=1`：按请求缓存词法 fallback 的每页查询词匹配，按当前历史重新计算 IDF 与分数，用 partial_sort 取严格相同的页面。查询、范围、截断及请求变化使缓存失效。不改语义评分优先级。
- `NINFER_SELECTION_DIFF=1`：在 RAM 保留上传位图的副本，重复位图跳过上传，变化只上传首尾差异间的区段。变化仍使用原同步 CUDA 拷贝，不增加 GPU 缓冲区。
- `NINFER_DEMOTE_BATCH=1`：仅将原顺序中连续且符合相同保护条件的完整页合并到同一 Host extent，最多64页；实际 chunk128 常为2页。保留计算流上的拷贝顺序、source pin、writer、coverage 和回收条件；较大 Host extent 申请失败时恢复 lookahead writer 并回到逐页路径。

三个开关只供该分支源码实验使用。v0.1.2 预编译包不实现它们。没有发布或自动替换日常引擎，也没有把它们设为部署默认。

## 判断与后续

基线两次冷预填充86.399/86.449秒，增量词法一次85.108秒，约缩短1.5%；叠加位图没有进一步稳定收益，批量搬运88.115秒反而更慢。续接与decode也未呈现一致改善，不能将其中某个较快数字称为总体提速。小百分比差异可能来自温度、驱动调度与测量波动；本轮保留稳定引擎，不将实验提升为默认。三项代码都不新增GPU分配，但会增加少量RAM元数据；D档整卡峰值较A/B/C多4MiB，采样无法排除瞬时峰值。

CPU与传输侧只能减少相应部分开销。进一步优化GPU注意力须先核对实际路由及复用静态库对应的实现，再对跳页/流水线内核做独立数值与Graph重放对照。本轮未修改GPU注意力算术，也未用缩小检索、删历史或改采样换速度。

构建沿用原工具链，重编全部受Program/PagedKVCache布局影响的Host单元及已有相关CUDA单元，链接其余原静态库；并非干净全量构建。候选二进制哈希见证据，仅用于本机实验，未替换Release资产。
